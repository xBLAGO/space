# UEL 0.3 — модель доверия и угроз

| Сценарий | Контроль | Остаточная граница |
|---|---|---|
| Согласованный откат source SQLite, privacy journal, local witness | Live nonce, pinned signer, сохранённые префиксы custody store | Custody state должен пережить этот откат |
| Старый подписанный ответ или подстановка checkpoint | Подпись, разные домены, request hash, nonce, stream, счётчики и корни | Offline-копия без свежего tip не доказывает актуальность |
| Потеря journal/witness/custody DB/head/key/config | Отказ чтения и записи. Автоинициализация потерянного состояния отсутствует | Доступность зависит от исходных control copies |
| Две конкурирующие ветки источника | File lock и SQLite transaction хранителя. Только одно продолжение | Первое подписанное отправителем продолжение предполагается заявлением доверенного source runtime |
| SQLite commit без durable head или потеря ACK | Подписанная последовательность custody и повтор fsync до ответа | Требуются корректные гарантии файловой системы |
| Коррупция производного индекса | Offline rebuild из исходного журнала, сверка источника, защищённый repair audit | Source corruption и утрата оригинальных доказательств требуют восстановления подтверждённой копии |
| Попытка использовать ремонт для удаления чужих данных | Ремонт не выдаёт сессию. Удаление выполняется штатным PrivacyService | Оператор с доступом к файлам уже обладает инфраструктурными возможностями |
| Откат backup после удаления | Прежние denials/holds и G09 остаются обязательными | Запрет физического восстановления носителей здесь не доказан |
| Утечка checkpoint | Частный экспорт 0600, отсутствуют payload и user IDs | Stream, счётчики и частота изменений сохраняют риск корреляции |
| Компрометация отправителя | Префикс старой истории нельзя заменить у честного хранителя | Истинность новых утверждений не гарантируется |
| Компрометация хранителя или совместный откат всех его контролей | Требуется независимая проверка и сохранённый оператором tip | Универсальное решение против такого отката не реализовано |
| Недоступность или чрезмерный запрос | Ограничения размера, Unix socket timeout, отсутствие автоматического retry | Один процесс обслуживает socket последовательно. SLO и DoS-устойчивость не измерены |

Исходные Asset/Help state machines, identity, память и миграционные контрольные суммы сохраняют прежние роли. Новые подписи не означают Human consent. Публичное распространение checkpoint и публикация агрегатов не включены.

Результат security review относится к локальной модели отказов и same-author тестам. Внешний аудит, удалённый оператор и независимое хранение должны быть подтверждены отдельно до допуска людей.

Новая категория данных — частные checkpoint, stream и ключи проверки. Для неё сохраняется риск корреляции по счётчикам и последовательности. В автоматических испытаниях данные и свежие ключи удаляются вместе с временным стендом. Ручной стенд удерживает custody history до завершения эксперимента. Эксплуатационная retention-политика для реальных участников не утверждена. Удаление retained checkpoint или ключа может лишить систему доказательства восстановления, поэтому автоматическая очистка этого хранилища отсутствует. Это ограничение должно быть согласовано с G04 до дальнейшего допуска людей.
