# Foundation 04: аудит персональной памяти

База изменений: `feat/foundation-04-semantic-memory`, commit
`25dcb0fae420b27916629b1686f07f6f96e5c446`.
Ветка проверки: `fix/foundation-04-memory-pilot`.

## Архитектура и границы

Telegram получает идентичность из отправителя сообщения; Mini App — из проверенного
Telegram initData. Оба разрешаются через `channel_links` в единый `blago_user_id`.
Отдельный Web-аккаунт объединяется с Telegram только через существующий одноразовый
код. Память и история читаются заново на каждый запрос, с фильтрацией по BLAGO ID.
Привязка не основана на совпадении имени или username.

`PersonalAssistantAgent` обрабатывает команды локально и вызывает ChatProvider для
обычного разговора. Hugging Face использует существующий OpenAI-совместимый
`/chat/completions`: один запрос ответа, без повторов при ошибке, и максимум один
дополнительный запрос извлечения. Экстрактор получает только последнее сообщение,
без истории и существующей памяти. Сохранение происходит через MemoryStore в
`memory_facts` и `semantic_memory`; история хранится отдельно в `dialogue_turns`.

## Найдено и исправлено

- LLM мог назвать отрицание, цитату, гипотезу или чужой факт личным утверждением.
  Добавлены локальные проверки всего сообщения, буквального evidence/value,
  типа связи и пространства ключей. Разметки `subject=self` теперь недостаточно.
  Несколько кандидатов с одним ключом отклоняются как неоднозначные.
- Явный запрет на запоминание имеет приоритет над разбором и командами сохранения.
  Отрицания не превращаются в положительные факты. Прямое отрицание проживания
  удаляет точно совпадающий старый город, без придумывания нового места.
- Ручное исправление раньше перекрывалось старой семантической записью.
  Теперь два представления согласуются транзакционно: ручное изменение переводит
  активную семантическую версию в superseded, семантическое обновление убирает
  одноимённую плоскую запись. Повтор той же версии не создаёт дубликат.
- `/forget` не принимал `skill:python` и ключи с точками. Теперь принимает;
  удаление и очистка физически удаляют строки всех версий из обеих таблиц одной
  транзакцией, с сохранением изоляции пользователей.
- При привязке аккаунтов могли сталкиваться ключи разных таблиц и повторные
  `telegram.*`. Теперь общий распределитель имён учитывает обе таблицы и все
  версии; история версий переносится вместе с оригинальными ID и supersedes_id.
- Кандидат потребности мог стать подтверждённым фактом в JSON-хранилище.
  Теперь такой backend пропускает кандидатов. В SQLite потребность остаётся
  candidate, не попадает в контекст фактов, видна в `/memory` с пометкой «не заявка»
  и доступна для удаления. Ни агент, ни экстрактор не создают `blago_needs`,
  платёжные заявки или внешние действия. Веб-формы создания заявок остаются
  отдельными действиями пользователя.
- После ошибки ответа локальный разбор всё равно менял память. Теперь при ошибке
  провайдера или невалидном ответе память не меняется, сохраняется безопасный ответ
  о недоступности. Ошибка анализа памяти не отменяет уже полученный полезный ответ.
  Проверяются типы, длины, confidence, JSON, глубокая вложенность и категория.
- Фильтр чувствительных данных дополнен распространёнными форматами токенов,
  номерами карт, телефонов, email, идентификаторами документов и реквизитов.
  Такие сообщения скрываются до отправки модели и записи истории; ответы
  фильтруются до возврата, включая последующий кэш Telegram. Фильтрация действует
  и при выборе старой памяти в LLM-контекст и импорте legacy JSON.
  Отдельная защищённая процедура хранения секретов не реализована: сохранение
  известных чувствительных сведений отклоняется.
- Простой локально разобранный факт, команды, запреты, неоднозначные и неперсональные
  сообщения больше не вызывают отдельный анализ памяти. Для остальных подходящих
  сообщений сохраняется максимум один дополнительный запрос. Общая блокировка
  диалога у SQLiteBlagoStore согласует Telegram, Web и привязку в одном процессе.

## Управление пользователем

- Просмотр: `/memory`, «что ты помнишь», Web/Mini App: профиль и API memory.
  Кандидаты доступны в ответе чата и поле `records` API.
- Исправление по показанному ключу: `исправь city на Казань`,
  `запомни city = Казань`, либо обычное «Теперь я живу в Казани».
- Удаление: `/forget city`, `/forget skill:python`, «забудь city»;
  кнопка «Забыть» в профиле для подтверждённых фактов.
- Очистка всей памяти: `/clear-memory`; история очищается отдельно `/clear-history`.
- «Не запоминай это» запрещает извлечение из текущего сообщения. Это не глобальная
  настройка выключения памяти и не команда удаления истории.

## Совместимость и ограничения пилота

Схема Foundation 04 не меняется; новая миграция не требуется. Старые записи читаются
в прежнем формате, evidence нужен только для новых ответов экстрактора и не добавляет
столбец. Старая модель, не выдавшая evidence, безопасно не добавит новый факт.
Существующие неоднозначные ключи не переименовываются автоматически.
Поведение удаления намеренно изменено с soft delete на удаление всех строк ключа.
История разговора и старые резервные копии не очищаются командой удаления факта;
это также не гарантирует криминалистическое стирание страниц SQLite/WAL.
Существующие рабочие данные не сканировались и не исправлялись.

Политика извлечения намеренно консервативна: смешанные сообщения с отрицаниями,
гипотезами или цитатами целиком пропускаются; поддерживаются явные формулировки
от первого лица на русском/английском. Сохраняется исходная формулировка значения,
без догадок о падежах и синонимах. Для сложного исправления есть явная команда.
Эвристики не являются универсальным DLP или доказательством истинности факта;
неразмеченный произвольный секрет невозможно надёжно распознать по одному тексту.
Инструкции модели не дают формальной гарантии против prompt injection.

Пилот рассчитан на один процесс приложения с общим SQLiteBlagoStore. Блокировка
диалогов не координирует несколько реплик/процессов и сериализует обращения разных
пользователей на время LLM. Для масштабирования нужен отдельный протокол блокировок.
Ошибки диска не маскируются под успех; изменения памяти откатываются транзакцией.
Запись пары реплик истории не составляет единую транзакцию с памятью;
гарантия восстановления после аварийного завершения процесса не добавлялась.
