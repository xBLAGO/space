# Приёмка ответов: живая модель и физические устройства

Статус: **NOT EXECUTED**, пока нет фактических ответов разрешённого live-провайдера и отдельных артефактов Android / iPhone. Предыдущие 532 теста, 11 HTTP и 7 browser checks проверяют локальные контракты и эмуляцию. Они не закрывают эту приёмку.

Исходный runtime: PR #41, `bac4955a579f212bf3823e7da4636af548a68afa`; runtime source `4850c16cce2b30e384dce281bcec073a72a99300`. Этот этап добавляет лабораторный инструмент / инструкции, не меняет production runtime, guard, API, migrations или checksums.

## 1. Разрешённый live-провайдер

Используется прежний отдельный test-only контракт `tools/help_test_provider.py`:

- `BLAGO_TEST_HF_TOKEN` — **только отдельный тестовый credential**, предоставленный через локальное окружение / secret manager, без записи значения в чат, Git, shell history или отчёт.
- `BLAGO_TEST_HF_MODEL` — явно выбранная владельцем модель и, если поддерживается, конкретный provider route. Никакого автоматического выбора самой дешёвой модели.
- `BLAGO_TEST_HF_APPROVED=synthetic-only` — разрешение именно на синтетический прогон.

`HF_TOKEN`, `OPENAI_API_KEY`, cached Hub login, production secrets и произвольные `.env` не читаются. Отсутствие отдельного допуска даёт `NOT EXECUTED`, `requests=0`, а не mock PASS. В текущем окружении предоставленных test credentials нет. Значения production credentials не проверялись.

```sh
# Из отдельного shell с подготовленными TEST credentials, patched SQLite и PYTHONPATH=.:src:
python -m tools.agent_context_live_check --output /tmp/blago-context-live.json
```

Инструмент создаёт новую временную SQLite с Identity, Help, Privacy, witness, fencing и явной agent-context миграцией. Перед каждым прогоном создаются новые вымышленные участники A / B; данные из существующей рабочей базы не принимаются. Основной integration launcher по-прежнему запрещает live provider. Отдельный инструмент использует явную test-only dependency injection, не отключая guard.

Предел — 96 provider requests, timeout 20 секунд на генерацию, обычный budget 384 tokens; прежнее однократное продолжение может увеличить бюджет ответа. Бесконечных retry нет. Точный расход и задержки фиксируются; это не обещание стоимости. Вызовы идут только на существующий HF inference router, не в production Space.

## 2. Единый сценарий A / B

| Шаг | Реплика / действие | Ожидаемое наблюдение |
|---|---|---|
| 1 | A, Web: «Меня зовут Алина» | Имя относится к A, а не к агенту; основание — заявление A |
| 2 | «Я живу в Перми» | `city=Перми`, проверяемый source turn/span; без независимой аттестации города |
| 3 | Знакомый в Уфе; гипотеза о переезде в Омск | Не становится текущим городом A; модель не выдаёт гипотезу за свершившийся переезд |
| 4 | Вымышленный рассказ «Сиреневый парус», просьба не сохранять; 35 других тем | Сохраняются только разрешённые факты. Темы и ответы в transcript доступны для оценки связности |
| 5 | «Где я живу?»; «Откуда ты это знаешь?» | Актуальный город, корректное происхождение; без выдуманной даты или независимого подтверждения |
| 6 | Название старого рассказа | C02: архивный поиск отсутствует. Корректна честная неопределённость. Если название повторено из видимой истории, это context echo, не доказательство retrieval |
| 7 | Связать Web A → Bot → Mini App | Канонический ID A сохраняется; старая Web session после linking отзывается штатно, выполняется новый вход |
| 8 | Mini App: «Я больше не живу в Перми, теперь живу в Томске» | Каноническая память меняется после успешной генерации/commit; сама локальная квитанция не доказывает качество LLM |
| 9 | Спросить город в Web, Bot, Mini App | Во всех **ответах** актуальный Томск; прежняя Пермь не выдаётся за текущее место |
| 10 | «Забудь мой город»; повторить вопрос во всех каналах | Факт и источник не используются; ответ прямо сообщает отсутствие сведений. Ошибка связи с моделью не засчитывается как такое признание |
| 11 | «Не запоминай это: я предпочитаю какао…» | Разговор продолжается; ни active memory, ни semantic records не меняются |
| 12 | Явно очистить историю; спросить предпочитаемый напиток | Долговременного предпочтения нет, ответ не придумывает его. Проверка отделяет temporary history от semantic memory |
| 13 | Спросить источник имени после очистки истории | C12: surviving fact с удалённым source имеет UNKNOWN; нельзя придумать исходную реплику |
| 14 | B, отдельная session: спросить город/напиток | B не получает факты A; trace не содержит чужих источников. Проверяется также сам ответ, не только пустая БД |

JSON содержит **input, answer, model_answer, model_answer_success, channel, participant alias, selected_facts с source/reason, memory_after, число requests**. Локальная квитанция / переработанный ответ приложения отделены от ответа модели. Технические transport IDs, session tokens, credentials и headers в отчёт не включаются.

## 3. Оценка фактических ответов

Для каждой критической реплики reviewer записывает точный ответ, `PASS / FAIL / UNKNOWN`, обоснование, source/span или отсутствие допустимого источника. Без этой оценки общий `answer_quality` остаётся `PENDING HUMAN REVIEW`.

- Связность и естественность: без повторного знакомства, лишних вопросов и ложного «я помню».
- Достоверность: актуальная запись соответствует ответу; предположение / чужое сообщение не становится фактом владельца.
- Исправление: нет прежнего значения в роли текущего; ссылка на источник соответствует новому сообщению.
- Удаление / неизвестность: прямое признание отсутствия данных; не догадка и не transport fallback.
- Вето: нет записи семантического факта; временное присутствие в текущем диалоге не объявляется нарушением долговременной памяти. Отдельная очистка истории проверяет границу.
- Изоляция: нет чужих имён, городов, предпочтений или происхождения в ответе B.
- Завершённость: пустой, оборванный, служебный ответ / 503 — наблюдаемый сбой, не PASS по фактам.

Автоматические state checks и наличие нужного слова не заменяют human review. Совпадение угаданного названия с исходным без доступного источника не закрывает C02.

## 4. Физический Android и iPhone

Нужны отдельные фактические прогоны. Ни Chrome mobile emulation, ни simulator, ни два browser contexts не считаются физическим устройством.

Предпосылки, которые сейчас не предоставлены:

1. Выделенный непроизводственный HTTPS test host, доступный обоим устройствам через утверждённый приватный канал; отдельные test volumes, journal и witness. `localhost` на компьютере недоступен телефону как тот же host.
2. Отдельный test Telegram bot / test Mini App с корректными origin и TLS. Не использовать / перенастраивать production bot, webhook, HF Space, DNS или секреты. Не отключать certificate, initData, CSRF, session и replay проверки ради запуска.
3. Два тестовых участника A / B. Для настоящего Telegram нужны реальные **идентификаторы тестовых Telegram-аккаунтов**, даже если профиль вымышленный. Это transport metadata, а не полностью синтетические IDs; до прогона нужен явный допуск владельца тестовых аккаунтов. Они не отправляются LLM и не публикуются в evidence.
4. Тестер с физическими устройствами. В отчёте достаточно версии ОС, браузера и Telegram; не собирать IMEI, MAC, серийный номер, fingerprint, телефон или список контактов.

На **каждом** устройстве пройти шаги 1–14. Начать Web A, связать test Bot штатным одноразовым кодом, открыть реальную Mini App, проверить общий профиль и source-state. После исправления и удаления проверить все три канала на обоих устройствах. Для B использовать отдельную session/browser profile и другой test Telegram account — не просто ещё одну вкладку с cookie A. Повторить после перезапуска стенда; не переносить чужие session cookies.

Артефакты: точные вымышленные входные реплики и ответы, время/номер шага, alias устройства, версии приложений, alias участника, результат каждого assertion, hash локальных evidence. Скриншоты — только test App, без реальных контактов, notifications, handles, cookies или initData. Приватные test credentials / transport identifiers не коммитить. Завершение — штатное удаление тестовых данных с существующими retained denials, без стирания control plane ради возврата доступа.

Шаблон: [device-review-template.json](device-review-template.json). Пока артефактов нет, Android и iPhone — **NOT EXECUTED**, даже если весь CI зелёный.

## 5. Непересматриваемые границы

- **C02:** возврат к произвольной старой теме за пределами текущего окна пока недоступен. Это не исправляется выдуманным summary или догадкой модели.
- **C12:** происхождение legacy-записи / удалённого источника остаётся UNKNOWN без подтверждаемой ссылки. Автоматического backfill нет.
- **C14:** перенос контекста между независимыми узлами — отдельная задача федерации. Несколько устройств с одним сервером её не доказывают.

Фактическая приёмка отражается в [матрице C01–C14](SCENARIOS.md). Этот этап не повышает общую пилотную готовность.
