## Навигация и приложение

На Home повторяются Information / Token / Sign In сверху и снизу. Языки представлены флагами; на внутренних страницах есть Back и внешние ссылки, включая документацию/социальные площадки. Отдельного первого пути «что работает сейчас → правила приватности → безопасный доступ» не наблюдается.

На четырёх EN страницах нет direct link на Web App #19 или его точный runtime URL. `/app` на публичном домене отвечает 404. Это не доказывает отсутствие приложения на другом хосте: его адрес, production SHA, настройки бота и состояние live auth здесь UNKNOWN. Ссылка `@xBLAGObot` сама по себе не подтверждает, что бот работает на #19 или открывает нужный Mini App.

В отдельном [xBLAGO/blago-mini-app](https://github.com/xBLAGO/blago-mini-app/tree/53137edbec9bd2acbcfe4c4967291303825fdd6a) найдены только `src/config.ts` и `src/components/NeedCard/NeedCard.tsx`. Первый содержит devnet Solana configuration; второй — React funding card с placeholder handler и остатками markdown/CSS в TSX. В дереве нет package manifest, entrypoint и импортируемого `NeedCard.css`. Это незавершённый прототип, не воспроизводимая альтернативная сборка Mini App #19 и не доказательство deploy или on-chain действия. Его не следует интегрировать в MVP как готовый UI.

## Визуальное качество, доступность, приватность

- Публичный сайт визуально отличается от тёмного спокойного shell #19: яркий анимированный фон, длинный текст, повторённые CTA. В проверенных desktop/mobile viewport нет горизонтального overflow и JS page errors; полноценный accessibility/performance аудит не проводился.
- В исходнике Home есть `user-scalable=no`, длинные абзацы размечены `h1`, а язык выбирается флагами. Требуются семантические headings, разрешённый zoom, текстовые названия языков, проверка contrast/focus/reduced motion и читабельности на настоящем телефоне.
- Home source содержит Yandex Metrika с `webvisor:true`, Google Tag Manager и gtag initialization. Наличие кода подтверждено; фактические объёмы отправки, запись сессий и конфигурация поставщиков UNKNOWN. В browser audit tracking requests блокировались. Не считать отсутствие ошибок доказательством consent compliance.
- В просмотренном markup нет наблюдаемого предварительного consent UI. Нужна отдельная проверка применимой политики, необходимости каждого трекера и настроек. Чат, память, auth и delete/export flow не должны получать такую telemetry по наследству от сайта.

## Предлагаемая структура сайта

1. **Главная:** человеческий смысл, простое объяснение разговора и добровольной помощи, точный статус разработки.
2. **Как это работает:** личное/общественное, явное подтверждение публикации, отсутствие автоматических обязательств, что пока не реализовано.
3. **Приватность и доступ:** память под контролем человека; способы входа; границы удаления; различие аккаунта и уникального физического человека.
4. **Статус и открытая разработка:** проверенные release notes, ограничения, ссылки на исходники и Draft discussions; не выдавать будущий протокол за текущую федерацию.
5. **Перейти к BLAGO:** только approved app URL и Telegram entrypoint после проверки release; до этого — статус испытаний, без обещания свободного доступа.

Token/инвестиционные материалы не должны оставаться основным маршрутом нефинансового MVP. Рекомендация — снять их с текущего продуктового пути либо явно архивировать после отдельного решения владельца и профильной проверки. Этот аудит не редактирует и не публикует страницы.

Пример предлагаемого текста для согласования: «BLAGO помогает человеку вести разговор, осмыслять потребности и добровольно взаимодействовать с другими людьми. Сейчас проект находится на этапе изолированных испытаний. Доступные функции и ограничения перечислены в статусе разработки». Не писать «пилот доступен» до прохождения gates.
