## Что исправляется

Участник определяется существующей аутентифицированной сессией / Telegram-привязкой, а не именем из разговора. Профиль участника передаётся отдельно от `AgentProfile`, только с разрешёнными `display_name`, `language`, `timezone`. Имя — выбранное обращение, не юридическая идентичность и не доказательство уникальности человека. Противоречащие выбранные имена не разрешаются догадкой: используется нейтральное обращение.

Небольшой постоянный контекст содержит актуальное имя и стиль ответа; остальные активные факты выбираются по запросу. Это позволяет найти сохранённое заявление после 35 промежуточных реплик, не передавая модели всю биографию. Произвольная старая тема, не сохранённая как разрешённый факт, всё ещё может выйти за окно 24 реплик / 24 000 символов: C02 закрыт только в части долговременных фактов, а не полной архивной семантической выдачи.

У новых записей `semantic_memory.source` хранится обратносовместимый указатель `...|context_turn:<id>`. Он связывается с фактически записанной пользовательской репликой внутри той же транзакции. Исходная запись, пара реплик и указатель откатываются вместе. Отдельного хранилища биографии, копии разговора или нового журнала нет.

Перед ответом указатель проверяется по владельцу, роли `user`, существованию реплики и совпадению минимального фрагмента. В модель передаётся только значение и его диапазон символов в исходной реплике, не полная реплика, содержащая другие факты. Для legacy-записей, удалённых источников и неподтверждённых ссылок происхождение — `UNKNOWN`; источник не восстанавливается по похожему тексту.

Статус SQLite `confirmed` сохраняет прежнюю совместимость, но контекст помечает проверенный source как `SELF_DECLARED`, `independently_verified=false`; запись без источника — `UNVERIFIED_STORED_CLAIM`, а не доказанное заявление человека. Уверенность экстрактора не является достоверностью утверждения. Гипотезы, цитаты, чужие сведения, отрицания и storage veto не становятся фактами владельца. В смешанном сообщении допускается только ограниченный случай: прямая декларативная часть перед запятой и последующим вопросом; произвольные союзы не разбираются как факты.

## Исправление и удаление: не только поиск памяти

Раньше удалённая запись могла повторно попасть в LLM из обычной истории. Новая явная миграция устанавливает триггеры исключения истории. Изменение памяти / профиля фиксирует в существующем HMAC privacy-журнале и witness глобальную границу ID реплик. Модель получает только историю выше границы. При исправлении или отзыве через агента граница также включает саму пару с исправлением: она может цитировать старое значение.

Пользовательская история не стирается этой проекцией. Допустимые факты остаются доступны через каноническую память и проверенную ссылку на источник. Цена консервативного решения — потеря сырого предыдущего контекста после изменения памяти; автоматического LLM-summary, которое могло бы воскресить удалённое, нет. Нельзя обещать полную непрерывность всех тем.

Удаление имени или очистка памяти также запрещают использовать прежнее профильное обращение. Отдельное последующее явное обновление `display_name` может снова разрешить его использование. Разрешение привязано к HMAC значения: восстановленный старый профиль не выдаётся за актуально разрешённое имя. Это контроль раскрытия в контексте, не новый способ входа и не стирание настройки профиля.

## Атомарность и G09

```mermaid
sequenceDiagram
    participant C as Web / Bot / synthetic Mini App
    participant G as Generation
    participant D as SQLite
    participant J as Privacy journal + witness
    participant L as Provider
    C->>G: сообщение и проверенная сессия / привязка
    G->>D: BEGIN IMMEDIATE, authorize, revision + epoch
    G->>J: проверка retained frontier / границ
    G->>D: scoped memory, profile, source pointers, history
    G->>D: COMMIT snapshot ticket
    G->>L: bounded context, без write-транзакции
    L-->>G: неподтверждённый текст
    G->>D: BEGIN IMMEDIATE, authorize + CAS
    G->>D: canonical memory + atomic pair + source binding
    G->>J: write-ahead exclusions + witness
    G->>D: COMMIT
    G-->>C: ответ; при конфликте безопасный отказ
```

Удаление и финальная сверка версии используют один существующий `BEGIN IMMEDIATE`. Если удаление первым завершило транзакцию, старая генерация не сохраняет ни память, ни пару, ни Bot receipt. Если commit ответа был первым, удаление исключает его из следующего контекста. Уже переданные провайдеру / человеку сведения нельзя отозвать задним числом. Автоматического повторного использования старого контекста нет.

Граница задаётся ID, не временем часов. Restore не может понизить независимо сохранённую границу; replay продвигает `sqlite_sequence`, чтобы новая реплика не получила старый исключённый ID. Snapshot без новой схемы при наличии новых retained событий отказывает до явной offline-миграции. Потеря журнала / witness не означает успешную проверку. Совместный откат всех доверенных копий остаётся ограничением Foundation 05.4.
