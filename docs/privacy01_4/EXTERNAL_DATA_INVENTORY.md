## Проверенные публичные условия — не deployment attestation

**Hugging Face router.** Публичная страница заявляет, что routed request/response bodies не сохраняются router, debugging logs ограничены30d без user data/tokens, и отсылает к политикам каждого downstream provider. Это ограниченное заявление о router, не доказательство обработки конкретного запроса BLAGO. [HF Security](https://huggingface.co/docs/inference-providers/security).

Provider selection допускает динамические `:fastest`/`:cheapest`, либо explicit provider suffix. В README BLAGO есть `:cheapest`; из него невозможно восстановить список прошлых processors. Перед real-user route нужны pinning, processor inventory и проверка settings/договора. [HF Inference Providers](https://huggingface.co/docs/inference-providers/index).

**Together — пример downstream различий, не установленный BLAGO backend.** Документация описывает prompt storage по умолчанию, отдельный opt-in обучения, organization-level отключение storage для ZDR и отдельный passthrough scope. ZDR не ретроактивен; для старых данных требуется отдельное удаление. Billing/usage metadata остаются. Не предполагаем, что настройки HF routing совпадают с настройками личного Together account. [Privacy](https://docs.together.ai/docs/privacy-and-security), [ZDR](https://docs.together.ai/docs/zero-data-retention).

**OpenAI API — возможный прямой route.** Official OpenAI documentation разделяет abuse-monitoring logs и feature-specific application state. По default мониторинг может хранить content до30d с исключениями; ZDR/Modified Abuse Monitoring требуют eligibility/approval и имеют endpoint limitations. Не доказано, что у BLAGO эти controls включены или применимы. [Data controls](https://developers.openai.com/api/docs/guides/your-data).

**Неизвестные custom/downstream routes** не получают по аналогии ни ZDR, ни обещание «не используется для обучения». Для Fireworks попробованная security-page была недоступна инструменту; утверждения о её сроках не делаются. Остальные processors нельзя определить без конкретного route/истории; review должен продолжиться после выбора backend, без private prompts в отчётах.

**Storage/CI sources.** [HF disk/volumes](https://huggingface.co/docs/hub/spaces-storage), [GitHub retention](https://docs.github.com/en/organizations/managing-organization-settings/configuring-the-retention-period-for-github-actions-artifacts-and-logs-in-your-organization), [workflow artifacts](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflow-artifacts). GitHub описывает default90d и configurable limits; изменение срока не распространяется задним числом. Наблюдённая expiry — metadata конкретного synthetic artifact, не лог о его удалении. Production настроек мы не меняли.

## Exit criteria для внешнего scope G04

Нужны утверждённые owners/processors, список реальных mounts/routes/copies и их датированный scope, access policy, договорные/технические retention/deletion controls, negative canary tests без секретов, конкретные retirement/deletion receipts с ограничениями, independent custody drill и обработка старых providers/snapshots. До этого external scope UNKNOWN и общий G04 не PASS.
