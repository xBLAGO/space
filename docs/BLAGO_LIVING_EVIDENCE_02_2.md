## Что выполнено

- Чистый stdlib-контракт ожидаемой матрицы: 40 шагов × 3 роли × 3 поверхности = 360 строк. CP1 после разрешения автора, CP2 после превью посредника, CP3 после отправки. Матрица фиксируется до подготовки и наблюдений.
- Подготовка одного нового синтетического seed и трёх отдельных копий SQLite/journal/witness/checkpoint для decline/revoke/consent. SHA начальной БД одинаков; каждая ветка использует один и тот же common_request_id и UI case `positive`. В seed имеются также два неиспользуемых legacy-обращения и одна приватная заметка — это явно не браузерный пролог.
- Операции согласия, поиска, приглашения, предложения и исполнения подготовщик не выполняет. Пустые audit/actual и отсутствие снимков сохраняют BLOCKED; команда завершается кодом 2.
- Offline-верификатор читает только bundle. Он не импортирует BLAGO, SQLite, браузер или сетевые клиенты; отказывается от путей SQLite, выхода за каталог и symlink. Проверяет хеши, целостность/непустоту PNG, наличие трёх ролей/поверхностей, маркеры, весь текст просьбы, allowlist успешного получения, смену контекстов и идентичность наблюдаемого автором состояния до/после получения/отказа.
- Роль локального HTTP-моста по-прежнему определяется IdentityRuntime-сессией. Дополнительные query/header/cookie `role` игнорируются; новый HTTP-тест сравнивает полный ответ с исходным. Это не выдача роли через cookie: используется только существующая аутентифицированная сессия.
- Продуктовые экраны и формулировки согласия не изменены. Новых миграций, доменных таблиц, Help lifecycle, identity или журнала нет. Старые VERSION/CHECKSUM неизменны.

Нет команды, которая честно завершает все три исхода PASS: команда ниже воспроизводит **подготовку** и выдаёт BLOCKED.

Исторические #44: 41 шаг и 340 JSON относятся к прежней методике, последовательным веткам и неполному набору поверхностей. Они не преобразуются в 02.2 PASS. Старый browser collector сохранял полный синтетический текст заметки B. Его CI-запуск в этой ветке заменён подготовкой BLOCKED, чтобы не создавать новые несовместимые artifacts; исторический отчёт и исходники сохранены. Все domain/HTTP regression tests сохраняются. Это снижение объёма нового browser evidence, а не улучшение готовности UI.

`src/xblago/domain/help_service.py:104–110`, `HelpService._row()`: до `offer` получатель C должен быть владельцем либо входить в `help_audience` опубликованной просьбы. `prepare():171` вызывает `_row()` до обработки предложения. Согласие на контакт не меняет аудиторию Help. C в seed не включён: предложение возвращает 404. Новый код обхода отсутствует.

Вариант дальнейшего решения — отдельно согласованный экран авторского изменения аудитории и перепубликации, выполняемый человеком после согласия C. До нового прогона требуется зафиксировать профиль `author_audience_change=true` и новую ожидаемую матрицу (378 строк). Скрытая подготовка или ретроактивное ослабление expected запрещены. Нынешний профиль false; consent остаётся BLOCKED.

## Запуск

Из этой рабочей копии в проверенной Python/SQLite-среде:

```sh
PYTHONPATH=.:src python -m tools.living_evidence_prepare --sandbox-root /tmp/blago-022-private-NEW --bundle /tmp/blago-022-bundle-NEW
PYTHONPATH=.:src python -m tools.living_bundle_verify /tmp/blago-022-bundle-NEW
```

Оба каталога должны отсутствовать, не быть вложенными друг в друга. Обе команды ожидаемо возвращают **2**, не PASS. Подготовщик запускает только временный локальный checkpoint-процесс; HTTP-сервер не открывает. Для локального UI позднее используется существующая команда `python -m tools.living_consent_lab serve --root /tmp/blago-022-private-NEW/decline --enable-local-sandbox` с явным синтетическим флагом согласно #44; bind только 127.0.0.1. Запуск сервера не является E2E-прогоном.

Синтетические логины, пароли и пути приватного стенда остаются в закрытом каталоге, вне bundle. Participant code C вычисляется из действующей синтетической идентичности, а не из надписи `RECIPIENT_ID_*`. Контрольный маркер: `NOTE_SECRET_BASELINE`; запрос целиком находится в manifest.seed.request_text. Полная заметка в bundle не включается.

Проверки: `python -m unittest tests.test_living_bundle tests.test_living_evidence_prepare tests.test_living_consent_lab -v`; полный regression и CI записываются в TEST_RESULTS.md. Требуется проверенная SQLite, указанный PYTHONPATH и разрешение локальных sockets. Docker локально недоступен — результат только по фактическому CI.
