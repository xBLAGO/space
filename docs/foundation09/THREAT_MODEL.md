# Foundation 09 — угрозы и ограничения

| Угроза | Контроль текущей итерации | Что остаётся |
|---|---|---|
| Подмена пользователя | Fresh active IdentityRuntime session, UID из неё, проверка VIEW и per-actor source audience | Policy — доверенная fixture-конфигурация, реальное коллективное управление не реализовано |
| Session принят за мандат | Полный эффект ограничен disposable forecast | Подписанное и долговечное человеческое согласование капитала требует отдельного протокола |
| Неподтверждённые средства | Условная spendable величина UNKNOWN при недостаточном level | Даже INDEPENDENTLY_VERIFIED здесь — допущение синтетического стенда, без верификации банка |
| Повтор/двойной расход | Ключи в одном расчёте, сохранение копеек, единый пул ресурсов, конфликт альтернатив | Между разными прогнозами нет общего денежного резерва. Durable double-spend protection для капитала NOT IMPLEMENTED |
| Несогласованность данных | Один guarded source snapshot, HMAC revision + epoch, fresh sessions | Нет атомарности источников с внешним платёжным провайдером |
| Stale plan после удаления/отзыва | Пересмотр source_revision, прежние holds/G09, актуальные ACL | План не является долгоживущим разрешением |
| Утечка | Read-only viewer scope, дополнительные actor ACL, без UID/token/личного текста в ответе | Предоставленные пользователем scenario-коды могут иметь смысл для него. Экспортировать произвольные сценарии публично нельзя |
| Crash/restore | Модель теряется и пересчитывается, исходные denials остаются | Денежная история и approvals не восстанавливаются, поскольку они не создаются |
| Самосогласование и сговор | Разные роли и запрет self-approval/self-execution | Независимость людей, Sybil и сговор не доказаны |
| Дискриминация | Нет богатства или вклада в ранжировании, открытый priority/deadline/tie-break | Срочность и tie-break требуют коллективного review и испытаний |
| Повреждение UEL/control loss | Исходный fail-closed LocalLedger и обязательный custodian | Совместный откат всех controls и независимый operator review остаются ограничениями 0.3 |
| DoS | 128 options, 512 steps, bounded numbers и guarded transaction | Нагрузка 100 участников синтетическая, SLO и реальная ёмкость не установлены |

Код не добавляет права к исходным Asset/Help операциям. База, миграции и key custody сохраняют исходные гарантии. Планирование не является альтернативой privacy deletion или consent flow. Итог для реальной экономики остаётся NO-GO.
